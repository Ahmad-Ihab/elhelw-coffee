# تجربة نظام بن الحلو

يمكن فتح ملف `Elhelw-ERP-Preview.html` في Chrome. يحتوي الملف على واجهة العمليات العربية وقاعدة بيانات محلية داخل المتصفح. يبدأ كل فتح للملف بتجربة جديدة ببيانات افتراضية. النسخة مخصصة لتجربة الوظائف ولا تصل إلى حسابات الشركة أو موقعها.

## تجربة بمستخدمين

1. افتح **رصيد المخزون** بحساب **مسؤول التشغيل**. تظهر كميات بن أخضر ومحمص وتشغيلة تنتظر الفحص.
2. اختر **مراجع الاعتمادات** ثم **المشتريات ← مراجعة اعتماد**. اعتمد أمر الشراء `PO-DEMO-01`.
3. ارجع إلى **مسؤول التشغيل** وافتح **المشتريات ← استلام تشغيلة**. اختر البند والموقع، وأدخل كمية ضمن المتبقي ورقم تشغيلة جديدًا.
4. في **الجودة**، افتح الفحص ثم سجّل نتيجته. النجاح يتيح الإفراج. الفشل يحجُز التشغيلة ويتيح فحصًا جديدًا بسجل مستقل.
5. افتح **مطابقة المخزون بالأستاذ العام** لمراجعة الفرق بين قيمة المخزون والرصيد المحاسبي. في **المبيعات المباشرة** توجد طلبية `SO-DEMO-01` لها وحدتان محجوزتان في تشغيلة `ROAST-01`.

## حدود قبول التشغيل

بوابة التطبيق تستخدم حساب Supabase الحالي وصلاحيات ERP المعينة لكل موظف. يعيّن مسؤول قاعدة الاختبار أول حساب إداري موثوق في مخطط ERP. يحتاج مسار الاعتمادات إلى موظف مختلف عن مُنشئ الأمر. تعيين الأدوار يقتصر على من يملك صلاحية `roles.manage`.

يستخدم تشغيل الشركة أكوادها، وحساباتها الرقابية، ومواقعها، ومعدلات العمولة، ووصفات التصنيع، واختبارات الجودة والسياسات المالية المعتمدة. يدخل مسؤول الرواتب البنود المعتمدة، ويدخل المحاسب أقساط الإهلاك وتوزيع فروق تحميل التكاليف. توزّع فاتورة نقل الاستلام حسب الوزن قبل خروج التشغيلة. تحتاج تكلفة نقل متأخرة بعد الصرف إلى تحديد نصيب المخزون والمصروف.

تعتمد تجربة ترحيل المخزون على جرد يشمل كود المصدر والتشغيلة والموقع والوحدة والكمية والقيمة. يطابق النظام الكميات حسب الوحدة والقيمة الإجمالية مع مجاميع رقابية مستقلة. يلزم عند تجربة الانتقال الكامل أيضًا مطابقة الذمم المفتوحة، وعهد المناديب، والخزائن، وقيود الأستاذ مع أرصدة الشركة في التاريخ نفسه. ملف التجربة مستقل عن سجلات الشركة. يتطلب الانتقال إلى التشغيل تجربة ببيانات معتمدة في بيئة منفصلة، واختبار حسابات Supabase وأجهزة العمل، ثم اعتماد مسؤول الشركة.

## نموذج ملف جرد تجريبي

يُختار الملف في **الأرصدة الافتتاحية ← قراءة ملف الجرد**. تُربط أكواد المصدر بالأصناف أولًا، ثم تُراجع المطابقة قبل الترحيل إلى دفتر فارغ. المجموع الرقابي مصدره محضر جرد معتمد مستقل عن سطور الاستيراد.

```json
{
  "reference": "COUNT-DEMO-01",
  "as_of": "2026-11-27",
  "expected_lines": 1,
  "expected_value": 125,
  "expected_quantities": {"KG": 2.5},
  "rows": [
    {"source_table": "warehouse", "source_key": "BEAN-01", "lot_code": "LOT-01", "location_code": "RAW", "base_unit": "KG", "quantity": 2.5, "total_value": 125}
  ]
}
```

لفحص الحسابات افتح **مطابقة أرصدة الشركة**. يقبل الملف مرجع الإقفال وتاريخه ومصفوفة أرصدة موثقة. يطابق `gl` كود حساب الأستاذ، و`treasury` كود حساب الخزينة، و`customer` و`supplier` كود الطرف. تستخدم أرصدة الأستاذ إشارة موجبة للمدين وسالبة للدائن. يستخدم رصيد المورّد إشارة موجبة للمبلغ المستحق له. يظهر أي رصيد فعلي غير صفري غاب عن الكشف ضمن الفروق.

```json
{"reference":"CLOSE-DEMO-01","as_of":"2026-11-27","balances":[{"kind":"gl","code":"RAW","amount":125},{"kind":"gl","code":"EQ","amount":-125}]}
```

## إعادة بناء التجربة

يبني اختبار GitHub باسم **ERP isolated database tests** نسخة HTML من ملفات SQL المرتبة وواجهة التطبيق نفسها. ينشئ قاعدة PostgreSQL 17 مؤقتة ويشغّل اختبارات الدورة التشغيلية، وحدود الصلاحيات، ومطابقة الجرد، والعهد، والمالية، والتخطيط. تتضمن الاختبارات عمليتين متزامنتين لمنع تكرار الترحيل أو تجاوز المخزون. يحفظ الاختبار نسخة HTML مع نتائج التشغيل.
