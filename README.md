# Elhelw Coffee — Distributor Management (MVP v2)

واجهة ويب عربية متوافقة مع الموبايل (PWA) لإدارة توزيع القهوة بنظام العهدة. هذه نسخة اختبارية محسّنة وليست اعتمادًا محاسبيًا أو تشغيلًا إنتاجيًا قبل اختبارها.

## ما تم تضمينه
- اسم وهوية التطبيق Elhelw Coffee.
- تسجيل دخول Supabase Auth وفصل صلاحيات الإدارة عن الموزع.
- منتجات وأسعار يحددها المدير فقط.
- مخزون عهدة مستقل لكل موزع؛ استلام البضاعة لا ينشئ مديونية.
- ربط الكافيهات بالموزع المسؤول.
- تسجيل طلبيات وتسليمات وفواتير.
- قواعد عمولة قابلة للتخصيص لكل موزع وصنف (نسبة أو مبلغ لكل كجم).
- تسجيل العينات كمصروف تسويقي مع خصمها من مخزون العهدة دون فاتورة أو عمولة.
- تسجيل تحصيلات الكافيهات وتوريدات الموزع للشركة.

## إعداد Supabase
1. افتح مشروع Supabase ثم SQL Editor.
2. افتح الملف `sql/schema.sql` وراجعه قبل التنفيذ، ثم شغّله مرة واحدة في مشروع جديد وفارغ فقط. لا تشغله فوق جداول موجودة.
3. من Authentication > Users أنشئ مستخدم المدير يدويًا. انسخ UUID.
4. في SQL Editor نفّذ بعد استبدال القيم: `insert into public.profiles(id,full_name,role) values ('USER-UUID','اسم المدير','admin');`
5. أنشئ مستخدم كل موزع من Authentication > Users، ثم أضف profile بدور `distributor` وسجل الموزع المرتبط به. مثال: `insert into public.profiles(id,full_name,role) values ('USER-UUID','Omar','distributor');` ثم `insert into public.distributors(user_id,name,phone) values ('USER-UUID','Omar','رقم الهاتف');`
6. بيانات الربط موجودة في `config.js` باستخدام Project URL وPublishable Key فقط. لا تضع Secret أو service_role في ملفات المتصفح أو GitHub.

## نشر التطبيق
ارفع محتويات المجلد إلى مستودع GitHub خاص أو عام حسب رغبتك، ثم فعّل GitHub Pages من Settings > Pages > Deploy from branch > main > /(root). افتح رابط HTTPS على الهاتفين ثم اختر Add to Home Screen / Install App.

## حدود النسخة الحالية التي يجب معرفتها
- الطلبية في واجهة MVP الحالية صنف واحد فقط؛ لا يوجد محرر متعدد الأصناف في شاشة واحدة.
- لا توجد بعد شاشة كشف حساب محاسبي كاملة أو مرتجعات أو تعديل/إلغاء الفواتير أو إدارة المستخدمين من داخل التطبيق.
- يجب اختبار تدفق التحصيل والتوريد والعمولات والعينات على بيانات وهمية قبل إدخال أي بيانات حقيقية.
- Service Worker يخزن واجهة التطبيق فقط؛ تسجيل الدخول والعمليات تحتاج اتصال إنترنت.
- هذه الحزمة لم تُختبر على قاعدة Supabase فعلية بعد، ولا ينبغي اعتبارها جاهزة للإنتاج.
